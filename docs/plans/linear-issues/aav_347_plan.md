# 开发方案 - AAV-347 🚨 staging smoke test failed — deployment rolled back

## 1. Issue 概述
本 Issue 反映在 staging 环境部署后，自动执行的 smoke test 失败，导致部署被回滚。需要排查失败原因，修复问题，确保后续部署的稳定性和自动化流程的健壮性。

## 2. 当前状态
- 状态：Backlog，尚未开始排查和修复
- 通过 GitHub Actions workflow 的日志可查看具体失败点，但尚无修复措施

## 3. 影响范围
- 主要涉及前端仓库 `aaveapy`（lovable 分支）部署流程及 CI/CD 配置
- 可能涉及后端接口稳定性（`aave-protocol-analysis`），需视具体失败原因确认

## 4. 实现方案

### 4.1 根因排查步骤
1. **查看失败日志**
   - 访问 Issue 描述中的 Workflow Run 链接，详细查看 smoke test 失败的具体步骤和错误信息
2. **定位失败环节**
   - 判断是前端构建失败、后端接口响应异常，还是 smoke test 脚本本身问题
3. **复现问题**
   - 本地或测试环境复现失败场景，确认问题是否稳定复现

### 4.2 修复方案设计
根据排查结果，采取相应措施：

- **构建失败**
  - 修复代码错误、依赖问题或构建配置
- **接口异常**
  - 检查后端服务健康，接口是否有变更，修复后端或调整前端调用
- **Smoke test 脚本问题**
  - 修正测试脚本逻辑，增加容错和超时处理

### 4.3 防止复发措施
- **完善 CI/CD 流程**
  - 增加更详细的日志和告警
  - 增加 smoke test 的覆盖面和稳定性
- **自动回滚与通知**
  - 确认自动回滚机制正常工作
  - 配置失败自动创建 Issue 并通知相关负责人
- **部署后自动验证**
  - 在部署后自动执行健康检查和关键接口测试

### 4.4 告警处理 SOP
- **失败时自动创建 Issue**
  - 现有 GitHub Actions 已实现，确保其稳定运行
- **负责人及时响应**
  - 设定负责人接收通知，优先处理
- **手动恢复流程**
  - 记录手动恢复步骤（如 `vercel promote` 命令）
  - 维护文档指导快速恢复生产环境

### 4.5 具体文件及代码修改建议
- `.github/workflows/deployment-smoke-test.yml`
  - 检查和优化 smoke test 步骤
  - 增加失败时的日志收集和通知
- `scripts/smoke-test.js` 或相关测试脚本
  - 修复测试逻辑，增强稳定性
- 可能涉及前端代码 `src/` 或后端接口 `backend/src/` 的修复
- 部署文档 `docs/operations/` 中补充自动回滚及手动恢复流程

## 5. 依赖关系
- 无直接依赖其他 Issue，但需关注后续 smoke test 相关失败（AAV-320、AAV-330-348 系列）
- 需与 DevOps 及运维团队协作确认部署和告警流程

## 6. 验收标准
- 在 staging 环境成功部署后，smoke test 全部通过，无失败
- 自动回滚机制正常触发且不会漏报
- 失败时自动创建 Issue 并通知相关人员
- 手动恢复流程文档完善且可执行
- 后续至少两次部署无类似失败
