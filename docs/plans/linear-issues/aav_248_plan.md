# AAV-248 推进全站无障碍校验、实施与规范建设 开发方案

## 1. Issue 概述
围绕前端站点（aaveapy/lovable 分支）推进无障碍（Accessibility, a11y）工作，涵盖规范建设、现状系统性校验、重点组件与页面的无障碍修复实施，以及无障碍工程化落地，最终形成可持续执行的无障碍标准和流程。

## 2. 当前状态
- 状态：Backlog，尚未开始
- 目前无障碍规范和系统性校验未见成型文档或代码实现
- 部分组件可能已有基础无障碍支持，但无整体覆盖和统一规范

## 3. 影响范围
- 仓库：aaveapy（lovable 分支）
- 主要涉及：`src/components/`、`src/pages/`、`src/lib/`（辅助工具）、`src/hooks/`（交互逻辑）
- 设计与文档同步（docs/目录或独立文档）

## 4. 实现方案

### 4.1 无障碍规范建设
- **目标**：制定一份覆盖全站的无障碍规范文档，明确通用原则、组件级和页面级要求。
- **步骤**：
  - 调研业界无障碍标准（WCAG 2.1 AA 级为基准）、React/TailwindCSS 无障碍最佳实践。
  - 结合项目现状，梳理语义结构、键盘交互、焦点管理、状态表达、标签文案、视觉对比等规范。
  - 形成文档（建议 Markdown 格式，放置于 `docs/accessibility/`），内容包括：
    - 语义HTML和ARIA使用规范
    - 键盘导航和焦点管理要求
    - 状态表达和动态内容提示规范
    - 颜色对比度和视觉设计要求
    - 组件无障碍设计原则（按钮、表单、弹窗等）
    - 页面结构和导航规范（标题层级、地标区域等）
  - 评审并迭代完善规范文档

### 4.2 全站无障碍校验
- **目标**：系统性检查现有前端代码，识别无障碍问题。
- **步骤**：
  - 使用自动化工具辅助检测（如 axe-core、Lighthouse、eslint-plugin-jsx-a11y）
  - 结合人工测试，重点检查：
    - 语义结构和ARIA属性
    - 键盘操作完整性（Tab/Shift+Tab、Enter、Space等）
    - 焦点顺序和焦点样式
    - 状态表达（选中、禁用、错误、展开/收起）
    - 标签和名称的清晰度
    - 页面标题层级和导航区域
    - 颜色对比度和动态反馈
  - 记录问题，形成问题清单，包含：
    - 问题描述
    - 影响组件/页面
    - 优先级（高/中/低）
    - 修复建议
  - 清单文档建议放置于 `docs/accessibility/`，格式可为 Markdown 或 Excel

### 4.3 重点组件与页面实施
- **目标**：优先修复和完善常用交互组件及关键页面的无障碍支持。
- **优先范围**：
  - 组件：按钮、链接、表单控件、下拉选择、Tabs、弹窗、表格、提示信息、导航区域
  - 页面：首页（Index）、Dashboard 主要页面（ChainPage、NotFound）
- **步骤**：
  - 根据问题清单，逐项修复代码：
    - 语义标签替换（如用 `<button>` 替代 `<div>`）
    - 补充或修正 ARIA 属性
    - 优化键盘交互逻辑和焦点管理
    - 增强状态表达的视觉和辅助技术支持
    - 确保标签文本清晰且可被辅助技术识别
    - 调整颜色对比度，满足 WCAG 标准
  - 编写或完善组件单元测试，覆盖无障碍相关行为
  - 进行人工辅助技术测试（屏幕阅读器、键盘导航）
  - 代码审查中加入无障碍检查点

### 4.4 工程化落地
- **目标**：将无障碍要求融入设计与开发流程，确保持续合规。
- **步骤**：
  - 在项目中引入无障碍自动检测工具：
    - ESLint 插件（eslint-plugin-jsx-a11y）集成到 CI
    - 预提交钩子（husky）执行无障碍检测
  - 设计评审和代码评审流程中加入无障碍检查项
  - 编写无障碍开发指南，供设计师和开发者参考
  - 定期组织无障碍培训和复盘
  - 建立无障碍问题跟踪机制，纳入日常迭代计划
  - 在文档中明确无障碍验收标准和测试流程

## 5. 依赖关系
- 无明显依赖其他未完成 Issue，但建议结合以下 Issue 关注：

## 6. 验收标准
- 无障碍规范文档完成并通过团队评审
- 全站无障碍问题清单完整，覆盖主要组件和页面
- 重点组件和页面无障碍问题修复完成，人工测试通过
- CI 集成无障碍自动检测，且无新违规警告
- 开发流程中无障碍要求明确，团队成员知晓并遵守
- 相关文档和培训材料交付

## 7. 复杂度评估
- 复杂度：High
- 理由：
  - 涉及全站多个组件和页面，工作量大
  - 需要系统性设计规范和技术方案
  - 需兼顾自动化检测与人工辅助测试
  - 需要跨团队协作（设计、开发、测试）
  - 工程化落地涉及流程和文化变更，难度较高
