# 开发方案 - AAV-322 开展全站无障碍审计并整理问题清单

## 1. Issue 概述
对现有前端站点（aaveapy/lovable 分支）进行系统性的无障碍（Accessibility）审计，重点检查读屏语义、键盘可操作性、焦点可见性、表单可理解性、导航结构、颜色对比和动态提示等方面。产出一份详细的问题清单，包含问题分类、影响范围、优先级和修复建议，为后续无障碍改进提供依据。

## 2. 当前状态
未开始。项目中尚无系统性的无障碍审计记录或问题清单。

## 3. 影响范围
- 仓库：aaveapy（lovable 分支）
- 主要涉及：前端 UI 组件、页面结构、交互逻辑

## 4. 实现方案

### 4.1 准备阶段
- 熟悉当前前端技术栈（React 19 + TypeScript + Vite + TailwindCSS）
- 确定审计工具和方法：
  - 自动化工具：axe DevTools、Lighthouse、WAVE、Accessibility Insights
  - 手工测试：键盘导航、屏幕阅读器（NVDA、VoiceOver）测试
- 制定审计范围，覆盖主要页面和关键组件：
  - 首页（Index）
  - ChainPage
  - Dashboard 相关组件（ReservesTable、TopOpportunities、FilterBar、Header、Portfolio）
  - 表单及交互控件

### 4.2 执行审计
- 使用自动化工具扫描页面，收集无障碍违规问题
- 结合手工测试验证自动化工具未覆盖的交互问题
- 重点检查以下方面：
  - 语义化标签使用（header、nav、main、section、aria-* 属性）
  - 键盘操作流程是否完整且无障碍死角
  - 焦点样式是否明显，焦点顺序是否合理
  - 表单控件标签是否明确且与控件关联
  - 导航结构是否清晰，是否支持辅助技术快速跳转
  - 颜色对比是否符合 WCAG AA 标准
  - 动态内容更新是否有无障碍提示（aria-live 等）

### 4.3 整理问题清单
- 按照以下字段整理问题：
  - 问题描述
  - 问题分类（语义、键盘、焦点、表单、导航、颜色对比、动态提示等）
  - 影响范围（具体页面或组件）
  - 优先级（高/中/低，依据影响用户体验和修复难度）
  - 修复建议（具体改进方案或参考文档链接）
- 采用 Markdown 格式文档，存放于 `docs/accessibility/` 目录，命名如 `accessibility-audit-report.md`

### 4.4 评审与发布
- 组织团队内部评审会议，讨论问题清单及优先级
- 根据反馈调整问题清单
- 将最终版问题清单纳入项目文档，作为后续无障碍改进的基线

## 5. 依赖关系
- 无直接依赖，但建议结合 AAV-323/321（无障碍相关后续改进）同步推进
- 需要团队成员配合进行手工测试和评审

## 6. 验收标准
- 产出一份完整的无障碍审计报告文档，内容涵盖所有重点检查项
- 报告中问题分类明确，优先级合理，修复建议具体可行
- 团队成员确认审计结果，认可问题清单的准确性和实用性

## 7. 复杂度评估
- 复杂度：Medium
- 理由：需要结合自动化工具和手工测试，涉及多个页面和组件，需跨团队协作，但不涉及代码改动，仅产出文档和问题清单。

---

此方案为开展全站无障碍审计的系统性规划，确保后续无障碍改进有据可依，提升产品的可访问性和用户体验。
