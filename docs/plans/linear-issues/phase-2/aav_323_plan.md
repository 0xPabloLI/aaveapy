# 开发方案：修复重点组件和关键页面无障碍问题 (AAV-323)

## 1. Issue 概述
基于全站无障碍审计结果，优先对重点组件和关键页面进行无障碍（Accessibility, a11y）修复。覆盖按钮、链接、表单控件、下拉选择、Tabs、弹窗、表格、提示信息、导航区域等核心交互模块，确保语义正确、键盘可操作、焦点管理合理、状态表达清晰且标签易理解。

## 2. 当前状态
- **状态**：未开始（Backlog）
- 代码中已有部分基础交互组件，但无障碍支持未系统完善，尚无专门无障碍修复相关代码或测试。

## 3. 影响范围
- **仓库**：前端仓库 `aaveapy`，lovable 分支
- 主要涉及 `src/components/dashboard/` 下重点组件及 `src/pages/` 关键页面

## 4. 实现方案

### 4.1 需求准备
- 获取并整理无障碍审计报告，明确重点无障碍问题清单及优先级
- 确定重点组件列表（如 Button、Link、Form Controls、Dropdown、Tabs、Modal、Table、Tooltip、Navigation）

### 4.2 设计与规范制定
- 制定无障碍开发规范文档，包含：
  - 语义化标签使用规范（如使用 `<button>` 而非 `<div>`）
  - ARIA 属性使用指南（aria-label, aria-describedby, role 等）
  - 键盘导航支持（Tab 顺序、Enter/Space 触发、Esc 关闭弹窗等）
  - 焦点管理策略（弹窗打开时自动聚焦，关闭时返回原焦点）
  - 状态表达（loading、错误、禁用状态的可访问提示）
  - 标签和提示信息的可理解性要求

### 4.3 具体开发步骤

#### 4.3.1 组件无障碍改造
- **按钮和链接**  
  - 确保所有交互元素使用正确语义标签  
  - 添加必要的 aria-label 或 aria-labelledby  
  - 支持键盘事件（Enter/Space）  
- **表单控件和下拉选择**  
  - 确保 label 与控件关联（for/id）  
  - 支持键盘操作和屏幕阅读器提示  
- **Tabs 组件**  
  - 使用 `role="tablist"`，`role="tab"`，`aria-selected` 等属性  
  - 支持箭头键切换焦点  
- **弹窗（Modal）**  
  - 使用 `role="dialog"`，`aria-modal="true"`  
  - 弹窗打开时聚焦第一个可操作元素  
  - 弹窗关闭时焦点返回触发元素  
  - 支持 Esc 关闭  
- **表格**  
  - 使用 `<th>` 明确表头  
  - 添加 `scope` 属性  
  - 提供表格描述（aria-describedby）  
- **提示信息和导航区域**  
  - 确保提示信息可被屏幕阅读器识别  
  - 导航区域使用 `<nav>` 标签，提供 aria-label  
- **全局键盘导航**  
  - 检查全站 Tab 顺序合理性  
  - 修复焦点丢失或陷阱问题

#### 4.3.2 页面级无障碍优化
- 重点页面（首页、Dashboard、ChainPage 等）进行无障碍测试与修复
- 确保页面结构语义化（header, main, footer 等）
- 确保动态内容更新（如异步加载数据）有适当的无障碍提示

### 4.4 测试与验证
- 集成无障碍自动化测试工具（axe-core, jest-axe）
- 编写无障碍单元测试覆盖重点组件
- 手工使用键盘导航、屏幕阅读器（NVDA/VoiceOver）进行验证
- 结合 Lighthouse 无障碍评分进行持续监控

### 4.5 文档与培训
- 更新组件库文档，补充无障碍使用说明
- 组织团队无障碍培训，提升整体意识和能力

## 5. 依赖关系
- 无直接依赖其他 Issue，但建议结合 AAV-321/AAV-322/AAV-324 等无障碍相关任务协同推进
- 需配合设计团队确认无障碍视觉设计规范

## 6. 验收标准
- 重点组件和关键页面无障碍审计中列出的问题均得到修复
- 自动化无障碍测试覆盖率达到 90%以上，且无严重违规
- 手工测试确认键盘操作流畅，焦点管理合理，屏幕阅读器能正确朗读内容
- 页面 Lighthouse 无障碍评分达到 90 分及以上
- 相关文档更新完毕，团队成员了解无障碍规范

## 7. 复杂度评估
- **复杂度**：Medium  
- **理由**：涉及多个核心组件和页面，需系统性改造和测试，且无障碍细节较多，需兼顾多种辅助技术和用户交互习惯，但技术实现基于已有 React 组件，难度适中。

---

此方案旨在系统提升前端关键交互模块的无障碍体验，确保符合 WCAG 标准，提升产品可访问性和用户体验。
