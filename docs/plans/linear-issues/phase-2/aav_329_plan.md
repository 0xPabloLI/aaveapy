# AAV-329 建立自动告警 issue 管理 SOP 开发方案

## 1. Issue 概述
建立一套针对自动告警类 Issue（如 smoke test 失败、同步失败等）的标准化管理流程（SOP），包括告警 Issue 的去重规则、主单维护、状态流转、关闭与重开规则，以及团队的执行方式。最终产出一篇结构清晰、可复用的 SOP 文档，指导团队高效统一地处理自动告警 Issue。

## 2. 当前状态
未开始。当前已有部分自动告警 Issue（如 smoke test 失败）由 GitHub Actions 自动创建，但缺少统一的管理规范和流程文档。

## 3. 影响范围
- 主要影响仓库：aaveapy（lovable 分支）及 aave-protocol-analysis（railway 分支）
- 主要涉及团队协作和运维流程，无直接代码变更，但可能涉及 GitHub Issue 模板和自动化脚本的调整

## 4. 实现方案

### 4.1 需求调研与现状梳理
- 收集现有自动告警 Issue 类型（smoke test 失败、数据同步失败等）
- 调查现有处理流程和痛点（是否存在重复 Issue、处理延迟、责任不明确等）
- 参考业界常见的自动告警管理最佳实践

### 4.2 制定管理规则
- **去重规则**  
  - 同类型告警在一定时间窗口内只保留一个主 Issue  
  - 通过标签、标题关键字、时间戳等判定重复  
- **主单维护**  
  - 明确主 Issue 负责人（Owner）  
  - 关联重复 Issue 到主 Issue（使用 GitHub 关联功能）  
- **状态流转**  
  - 定义 Issue 状态流转规范（New → Investigating → Fixed → Closed）  
  - 规定状态变更触发条件和责任人  
- **关闭/重开规则**  
  - 关闭条件（问题确认解决，且无复现）  
  - 重开条件（问题复现或新证据出现）  
- **团队执行方式**  
  - 告警响应时限  
  - 责任分配与协作流程  
  - 定期回顾和优化流程

### 4.3 编写 SOP 文档
- 使用 Markdown 格式，结构清晰，包含以下章节：  
  - 背景与目的  
  - 适用范围  
  - 术语定义  
  - 告警 Issue 类型说明  
  - 管理规则详解（去重、主单、状态流转、关闭/重开）  
  - 团队执行流程  
  - 常见问题与 FAQ  
  - 附录（相关工具、脚本链接等）

### 4.4 相关工具和自动化支持（可选）
- 评估是否需要调整现有 GitHub Actions 脚本，支持自动关联重复 Issue  
- 设计标签体系支持自动分类和筛选  
- 制作 Issue 模板，规范告警 Issue 创建格式

### 4.5 内部评审与培训
- 组织团队评审 SOP 文档，收集反馈并修订  
- 通过内部会议或文档分享，培训团队成员熟悉 SOP

### 4.6 发布与持续改进
- 将 SOP 文档纳入项目 Wiki 或 docs 目录，方便查阅  
- 定期回顾告警 Issue 管理效果，持续优化 SOP

## 5. 依赖关系
- 无直接代码依赖，但建议配合 AAV-320、AAV-330 至 AAV-348 等 smoke test 自动告警 Issue 的根因排查和处理流程  
- 可能依赖 GitHub Actions 自动化脚本的调整（如自动关联 Issue）

## 6. 验收标准
- 产出一篇结构完整、内容详实的自动告警 Issue 管理 SOP 文档  
- 团队成员均能理解并按照 SOP 处理自动告警 Issue  
- 自动告警 Issue 去重、主单维护、状态流转等规则在实际工作中得到执行  
- 相关 GitHub Issue 模板和标签体系（如有）上线并使用  
- 通过一次实际自动告警事件验证 SOP 流程的有效性

## 7. 复杂度评估
- 复杂度：Low  
- 理由：主要是流程梳理和文档编写工作，无复杂代码实现，重点在于规则设计和团队协作规范制定。若涉及自动化脚本调整，复杂度略增，但仍属中低级别。
