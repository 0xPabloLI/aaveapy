# 开发方案 - AAV-106 自动识别白名单

## 1. Issue 概述
实现自动识别用户是否在白名单中功能，提升访问控制和权限管理的自动化水平。当前系统已有 `whitelistOnly` 标志，但缺少自动识别和动态校验用户白名单状态的机制。

## 2. 当前状态
- **状态**：未开始
- **现状**：  
  - 后端已有 `whitelistOnly` 标志字段，但无自动识别白名单用户的逻辑。  
  - 前端无钱包连接和用户身份识别功能，无法动态判断用户是否属于白名单。

## 3. 影响范围
- **仓库**：  
  - 前端：`aaveapy/lovable` 分支  
  - 后端：`aave-protocol-analysis/railway` 分支

## 4. 实现方案

### 4.1 后端实现

#### 4.1.1 新增白名单数据存储
- **文件**：`backend/src/services/persistenceService.ts`  
- **操作**：  
  - 新增数据库表 `whitelist`，存储白名单地址及相关元数据（如添加时间、备注等）。  
  - 编写对应的迁移脚本放入 `backend/migrations/`。

#### 4.1.2 白名单接口
- **文件**：`backend/src/controllers/whitelistController.ts`（新建）  
- **功能**：  
  - 提供接口查询地址是否在白名单中（GET /api/whitelist/:address）。  
  - 提供接口管理白名单（增删改，需鉴权）。

#### 4.1.3 白名单校验逻辑集成
- **文件**：`backend/src/routes/index.ts`  
- **操作**：  
  - 在相关需要鉴权的API路由中，调用白名单校验接口，自动识别请求地址是否在白名单。  
  - 返回白名单状态给前端。

### 4.2 前端实现

#### 4.2.1 钱包连接功能
- **文件**：`src/components/Header/WalletConnect.tsx`（新建或扩展）  
- **功能**：  
  - 集成主流钱包连接（MetaMask、WalletConnect等）。  
  - 获取用户地址。

#### 4.2.2 白名单状态获取
- **文件**：`src/hooks/useWhitelist.ts`（新建）  
- **功能**：  
  - 调用后端 `/api/whitelist/:address` 接口，判断当前连接钱包地址是否在白名单。  
  - 返回白名单状态。

#### 4.2.3 UI调整
- **文件**：`src/components/FilterBar/FilterBar.tsx` 或其他关键页面组件  
- **操作**：  
  - 根据白名单状态，动态显示或隐藏对应功能模块。  
  - 若用户不在白名单且 `whitelistOnly` 为 true，显示提示信息或限制访问。

### 4.3 其他

#### 4.3.1 配置管理
- **文件**：`backend/src/config.ts`  
- **操作**：  
  - 新增白名单相关配置项（如是否开启白名单功能、白名单API路径等）。

#### 4.3.2 安全与权限
- 后端白名单管理接口需鉴权，防止未授权操作。

## 5. 依赖关系
- 依赖钱包连接功能的实现（前端）  
- 依赖数据库迁移和持久化支持（后端）  
- 可能依赖 AAV-66（Whitelist/blacklist）部分功能完善

## 6. 验收标准
- 用户连接钱包后，系统能自动识别其是否在白名单中。  
- 白名单状态正确反映在前端UI，控制访问权限。  
- 后端白名单管理接口功能完整且安全。  
- 相关API响应时间符合性能要求。  
- 单元测试覆盖新增白名单逻辑，集成测试验证前后端联动。

## 7. 复杂度评估
- **复杂度**：Medium  
- **理由**：涉及前后端多处改动，数据库设计及迁移，钱包连接集成，权限控制，需保证安全和用户体验，工作量适中。

---

此方案为自动识别白名单功能的整体开发指导，建议分阶段实施，先完成后端白名单存储与接口，再实现前端钱包连接及状态展示，最后联调测试。
