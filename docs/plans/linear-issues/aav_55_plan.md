# 开发方案 - AAV-55 版本切换功能

## 1. Issue 概述
实现一个版本切换功能，支持用户在“机构大客户版”和“小额理财版”两种界面/功能模式之间切换。不同版本可能在展示内容、功能权限、数据粒度等方面有所区别，以满足不同用户群体的需求。

## 2. 当前状态
未开始。代码库中暂无版本切换相关功能或界面区分的实现。

## 3. 影响范围
- 前端仓库：aaveapy/lovable 分支（主要实现版本切换的UI和逻辑）
- 后端仓库：aave-protocol-analysis/railway（可能需要支持不同版本的数据接口或权限控制）

## 4. 实现方案

### 4.1 需求确认与设计
- 明确“机构大客户版”和“小额理财版”两者的具体差异点（功能、数据展示、权限等）
- 设计版本切换入口（如Header右上角按钮或侧边栏）
- 确定版本切换后前端如何调整展示和调用的API

### 4.2 前端实现

#### 4.2.1 版本状态管理
- 在前端全局状态管理（如React Context或状态管理库）中新增`versionMode`状态，值为`"institutional"`或`"retail"`
- 支持通过UI切换该状态，并持久化（localStorage或cookie）

#### 4.2.2 版本切换UI
- 在`src/components/Header/`新增或修改组件，添加版本切换按钮或下拉菜单
- 版本切换后触发状态更新，刷新相关组件显示

#### 4.2.3 版本差异化展示
- 根据`versionMode`状态，调整Dashboard、ReservesTable、TopOpportunities等关键组件的展示逻辑
- 例如机构版显示更详细数据、更多筛选项，小额理财版简化界面、突出易用性
- 可能需要新增或修改hooks（如`useAaveMarkets`）以支持不同版本的数据请求参数

#### 4.2.4 API请求差异
- 根据版本模式，前端请求后端接口时带上版本标识（如请求头或查询参数）
- 方便后端根据版本返回不同数据或权限控制

### 4.3 后端支持（可选，视具体需求）

#### 4.3.1 版本识别
- 在Express中间件中解析前端传来的版本标识（header或query）
- 根据版本，调整返回数据结构或过滤部分数据

#### 4.3.2 权限与数据差异
- 机构版可能返回更完整的市场数据、历史数据或高级指标
- 小额理财版返回简化数据，避免复杂指标或敏感信息

#### 4.3.3 API文档更新
- 更新OpenAPI文档，说明版本参数及不同版本接口差异

### 4.4 持续集成与部署
- 增加版本切换相关的单元测试和集成测试（前端组件测试、接口测试）
- 在部署流程中验证版本切换功能正常

## 5. 依赖关系
- 需先明确两版本的具体功能需求（可与产品/设计沟通）
- 可能依赖 AAV-55 相关的权限管理或用户身份识别功能（若后续需要）

## 6. 验收标准
- 用户可以在界面明显位置切换版本
- 切换后页面内容和功能根据版本正确变化
- 前端请求带版本参数，后端根据版本返回对应数据
- 无明显性能或UI异常
- 单元测试覆盖版本切换逻辑
- OpenAPI文档更新并通过验证

## 7. 复杂度评估
**Medium**

理由：
- 需要前后端配合实现版本区分
- 涉及全局状态管理、UI调整和接口变更
- 需保证切换流畅且数据准确
- 但整体功能较为常见，技术难度中等

---

以上方案为初步设计，具体细节可根据产品需求进一步细化。
