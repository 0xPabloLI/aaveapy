# 开发方案：AAV-321 整理全站前端无障碍规范

## 1. Issue 概述
梳理并沉淀适用于全站前端（aaveapy/lovable 分支）的无障碍（Accessibility, a11y）规范，涵盖通用原则、组件级和页面级要求，统一语义结构、键盘交互、焦点管理、状态表达、文案标签、视觉对比和动态反馈等标准，形成可执行的规范文档，为后续开发和验收提供依据。

## 2. 当前状态
- 状态：Backlog，尚未开始
- 代码层面无系统性无障碍规范文档或统一标准
- 可能存在部分无障碍实践但无集中沉淀

## 3. 影响范围
- 仓库：aaveapy（lovable 分支）
- 主要涉及：`src/components/`、`src/pages/`、`src/lib/`（工具函数）、`src/hooks/`（交互相关）

## 4. 实现方案

### 4.1 需求调研与资料收集
- 调研主流无障碍标准（WCAG 2.1/2.2、ARIA规范）
- 参考 React/TailwindCSS 社区无障碍最佳实践
- 结合项目现有代码结构和业务特点，梳理适用点

### 4.2 规范文档编写

#### 4.2.1 通用原则
- 语义化HTML标签使用规范（例如：button、nav、main、header、footer等）
- ARIA属性使用原则（aria-label, aria-live, role等）
- 颜色对比度最低标准（符合WCAG AA）
- 键盘导航支持（Tab顺序、Enter/Space激活）
- 焦点管理（初始焦点、焦点环、焦点陷阱避免）
- 动态内容的无障碍提示（aria-live区域、状态变化通知）
- 文案标签规范（清晰、简洁、易理解）

#### 4.2.2 组件级要求
- 针对核心组件（ReservesTable, FilterBar, Header, Portfolio等）编写无障碍设计要求
- 交互组件键盘支持（如表格排序、筛选输入框、按钮、切换开关）
- 组件状态表达（禁用、加载、错误状态的无障碍提示）
- 图标及装饰元素的无障碍处理（隐藏或提供文本替代）

#### 4.2.3 页面级要求
- 页面结构语义化（主导航、内容区、辅助导航）
- 页面跳转焦点管理（路由切换后焦点置于页面标题或主要内容）
- 弹窗/模态框无障碍处理（焦点锁定、关闭快捷键）
- 表单及交互流程无障碍提示

### 4.3 规范文档存放
- 新建目录 `docs/accessibility/`
- 主要文档文件：`general-principles.md`, `component-guidelines.md`, `page-guidelines.md`
- 结合示例代码片段和推荐实践

### 4.4 规范推广与落地建议
- 在 `README.md` 或团队 Wiki 中链接该规范
- 结合代码评审流程，增加无障碍检查点
- 推荐使用辅助工具（axe-core、Lighthouse、eslint-plugin-jsx-a11y）集成到开发流程
- 规划后续针对核心组件的无障碍重构或优化任务
