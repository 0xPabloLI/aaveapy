# AAV-332 开发方案

## 1. Issue 概述
本 Issue 是针对 staging 环境部署后自动触发的 Smoke Test 失败告警，导致部署被回滚。需要排查失败根因，修复问题，确保后续部署稳定通过 Smoke Test，避免频繁回滚和人工干预。

## 2. 当前状态
- 状态：Backlog，尚未开始排查和修复。
- 部署失败发生在 commit `4639771`，具体失败原因需通过 GitHub Actions 日志进一步分析。

## 3. 影响范围
- 主要涉及前端仓库 `aaveapy` 的 `lovable` 分支的 CI/CD 流程。
- 可能涉及 GitHub Actions 工作流配置文件 `.github/workflows/deployment-smoke-test.yml`。
- 可能间接影响 Vercel 部署和环境配置。

## 4. 实现方案

### 4.1 根因排查步骤
- **查看失败日志**  
  访问 [GitHub Actions 失败日志](https://github.com/0xPabloLI/aaveapy/actions/runs/25832599430)，定位具体失败的测试或检查步骤。  
- **分析失败原因**  
  根据日志内容判断是代码缺陷、环境配置问题、依赖版本冲突，还是外部服务不可用等。  
- **回溯相关代码变更**  
  查看 commit `4639771` 及其前后提交，确认是否引入了破坏性改动。  
- **本地复现问题**  
  在本地或测试环境运行 Smoke Test 脚本，确认问题是否可复现。  

### 4.2 修复方案设计
- **针对具体失败点修复**  
  例如修复前端组件错误、接口变更未同步、环境变量缺失等。  
- **完善 CI/CD 配置**  
  确认 `.github/workflows/deployment-smoke-test.yml` 中的环境变量、权限设置、依赖安装步骤无误。  
- **增强错误日志和告警**  
  增加更详细的日志输出，便于未来快速定位问题。  
- **自动回滚与恢复流程优化**  
  研究并配置 Vercel 自动回滚与自动分配域名的正确流程，避免手动干预。  

### 4.3 防止复发措施
- **增加 Smoke Test 覆盖面**  
  补充更多关键路径的自动化测试，提前捕获潜在问题。  
- **引入预发布环境验证**  
  在合并到 `lovable` 分支前，增加预发布环境的 Smoke Test。  
- **完善部署文档和 SOP**  
  明确部署失败时的处理流程，包括回滚、通知、修复步骤。  

### 4.4 具体文件修改建议
| 文件路径 | 变更内容 |
| -------- | -------- |
| `.github/workflows/deployment-smoke-test.yml` | 检查并修正工作流配置，增加日志详细度，确保环境变量正确传递 |
| `src/` 或相关前端代码文件 | 修复导致 Smoke Test 失败的具体代码缺陷 |
| `docs/operations/`（如无则新建） | 编写部署失败处理 SOP 文档 |
| Vercel 项目设置 | 配置自动分配生产域名，优化回滚策略 |
